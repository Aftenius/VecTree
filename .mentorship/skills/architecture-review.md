# Skill: Architecture Review

Используется, когда проверяю структуру проекта, слои, границы модулей, выбор паттернов.

## Что проверяю

- **Направление зависимостей**: domain не импортирует infrastructure; зависимости внутрь.
- **Разделение слоёв**: domain / application (use cases) / infrastructure / presentation.
- **Границы модулей**: где проходит шов между фичами; нет «god-модулей».
- **Порты и адаптеры**: репозитории/провайдеры за интерфейсами, а не конкретные реализации.
- **DI**: составлены ли провайдеры; нет ли service locator / глобального состояния.
- **Явность**: конфиг, ошибки, транзакции — явные, а не «магия».
- **Тестируемость**: можно ли подменить внешний мир без моков «насквозь».

## Красные флаги

- Бизнес-логика в эндпоинтах или в моделях ORM.
- Импорт `sqlalchemy`/`httpx`/`boto3` из domain-слоя.
- Циклические зависимости пакетов.
- Синглтоны и глобальные сессии БД.

## Формат вердикта

Уровень + список замечаний по важности. Если ± senior — коротко подсветить trade-offs и не выдавать задачи.

## Материал для изучения (если ниже уровня)

- Clean Architecture (Robert C. Martin) — правило зависимости.
- «The Clean Architecture» + Ports & Adapters (Hexagonal).
- DDD: aggregates, bounded contexts, repository/UoW.
